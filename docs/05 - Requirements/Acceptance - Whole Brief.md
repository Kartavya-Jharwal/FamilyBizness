# Whole Brief Acceptance

This is the acceptance contract for completing the assignment platform, not a declaration that the rows pass. Product identity lives in [Identity](../00%20-%20Canonical/Identity.md). A family selects its own constitution/case; Golden Bird is one supplied worked example. The [release matrix](Release%20-%20MVP%20Acceptance%20Matrix.md) records current verification.

## Completion standard

A capability needs editable validated inputs, a working calculation or state transition, a visible result, persistence where appropriate, and evidence of verification. A heading, static card, explanatory paragraph, disconnected scenario, or navigation link does not satisfy a capability. Hypothetical inputs must be identified; outputs must be reproducible from those inputs. Missing or invalid inputs must not silently become zero or fictional defaults in reports.

## Audit finding at start of completion work

The earlier implementation covered useful isolated calculations and workflow slices, but not this complete contract. In particular, source mappings did not enforce parameters; allocation optimisation used a five-percentage-point grid; financial data were a single flat worksheet; estate liability used an assumed effective rate; recurrence was descriptive; philanthropy was a static sample register. Those implementations must not be cited as completion of the respective requirements.

## Population and release boundary

The prepared office uses the [Smith Family Constitution](../00%20-%20Canonical/Smith%20Family%20-%20Constitution.md). Visitor profiles share its existing saved records. Earlier independent cases and administrative revision/import tools remain available as secondary maintenance/recovery capabilities. Production authentication, donor servers/synchronization and financial/legal execution are excluded by the static-MVP contract.

The release matrix separates verified product behavior from genuine institutional/team submission inputs, which the software cannot invent. Source snapshots, user-authored parameters and prototype workflow records are retained for review and export.
